# 개인 블로그 화면별 설계안

기준일: 2026-10-15 · 상태: 문서 제안, 구현 전  
공통 기준: [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md)  
목표: 현재 Token Meter 디자인의 표현을 유지하고 기존 블로그의 콘텐츠·탐색에 적용

## 1. 정보 구조와 공통 구성

| 화면 | 기존 경로·기능 | 설계 방향 |
| --- | --- | --- |
| 메인 | `/` | 개인 소개 → 최신 글 → 카테고리 |
| 게시글 목록 | `/blog/` | 전체 글과 검색·정렬·페이지 탐색 |
| 게시글 상세 | `/blog/[...slug]/` | 제목 → Markdown + TOC → 이전·다음 |
| 카테고리 | `/category/`, `/category/[tag]/` | 카테고리 탐색과 동일한 글 목록 |
| 검색 | `/blog/?q=…`, 카테고리 안에서는 현재 경로의 `?q=…` | 검색 상태를 하나의 화면으로 설계. 별도 `/search/` 라우트 신설은 필수 아님 |

모든 화면의 공통 헤더: 개인 워드마크 / 홈 / 글 / 카테고리 / 검색 / 테마.
워드마크 콘텐츠는 기존 `SITE_TITLE`, 개인 소개는 `lib/site.js`의 실제 이름·소개를
사용한다. 원본의 큰 파란 푸터 표현은 유지하고 링크는 실제 개인 GitHub와 위로 이동으로 구성한다.
현재 알려지지 않은 이메일·SNS 주소나 원본 작성자의 연락처를 개인 연락처로 채우지 않는다.

검색·분류·정렬·이전·다음은 기존 데이터 동작을 유지한다. 카테고리와 태그는
현재 같은 `post.tags` 데이터에 연결되어 있으므로 별도의 새 분류 체계를 만들지 않는다.

아래 구조도는 배치와 정보 순서를 나타내며 화면 구현물은 아니다.

## 2. 메인 페이지

### 구조

```text
┌ 공통 헤더 ──────────────────────────────────────────┐
│ 개인 이름                     홈  글  카테고리  검색  테마 │
├────────────────────────────────────────────────────┤
│ 개인 이름 또는 블로그명.                   파란 ✳       │
│ 소개 문장                         글 보기 →           │
│ 현재 작성한 소개                                      │
├────────────────────────────────────────────────────┤
│ 최신 글                              모두 보기 →      │
│ 날짜·카테고리 │ 제목 / 요약 / 태그                      │
│ ─────────────────────────────────────────────────── │
│ 날짜·카테고리 │ 제목 / 요약 / 태그                      │
├────────────────────────────────────────────────────┤
│ 카테고리                                              │
│ 이름 / 실제 글 수 / 이동 링크                          │
├ 파란 공통 푸터 ──────────────────────────────────────┤
└────────────────────────────────────────────────────┘
```

### 디자인 적용

Hero는 원본 detail-title-row와 detail-summary를 그대로 역할 전환한다.
개인 이름은 원본의 display 크기·weight 550, 끝점과 작은 별표는 accent를 사용한다.
소개는 muted 14px / 1.95이며 원본과 같은 최대 640px 폭이다.
별표는 Hero에만 한 번 사용하고 700px 이하에서는 원본처럼 숨긴다.

주요 동작은 `글 보기`로 한 개를 둔다. 최신 글은 기존 `getFeaturedPosts()`가
반환하는 최대 5개를 표시한다. `최신 글` 위에 추가 eyebrow·가짜 숫자·영문
장식 문구를 붙이지 않는다. 카드 이미지가 없는 글에도 가짜 썸네일을 만들지 않는다.

최신 글 PostRow는 선 + 24px 위아래 여백, desktop 25px 제목 / 14px 요약이다.
전체 목록과 같은 컴포넌트를 사용한다. 카테고리는 이름과 실제 글 수를 보여주는
선으로 나뉜 행으로 구성한다. 제품 설명용 스크린샷 갤러리를 메인에 자동 추가하지 않는다.

### 모바일과 상태

Hero 소개·동작은 700px 이하 한 열. 800px 이하의 글 메타는 제목 위로 이동한다.
최신 글이 없으면 `아직 등록된 글이 없습니다.`와 같은 실제 상태 문장만 표시한다.
목록 제목과 푸터 위치를 유지하고, 글 수를 채우기 위한 샘플 게시물은 넣지 않는다.

## 3. 게시글 목록

### 구조

```text
공통 헤더
글.
짧은 목록 설명
───────────────────────────────────────────
검색 입력 + 실행       카테고리        정렬
실제 글 수 / 선택된 조건
───────────────────────────────────────────
날짜·카테고리       글 제목
                    요약 1–3줄 / 태그
───────────────────────────────────────────
동일한 PostRow 반복
───────────────────────────────────────────
이전 원형 버튼       현재 페이지 / 전체       다음 원형 버튼
공통 푸터
```

`글.`은 원본 display 토큰을 사용하고 제목 아래 충분한 여백을 둔다.
목록 영역은 원본 상세 섹션의 얇은 상단 선을 반복한다. 글 전체를 둥근 카드로
감싸지 않는다. 제목 hover는 색만 accent로 바뀌고 밑줄·상승·그림자가 생기지 않는다.

날짜는 실제 `lastModified || date`를 표시하며 label로 `수정일`을 명확히 한다.
태그는 `TagLink`를 사용한다. 읽기 시간은 데이터에 있더라도 기본 목록에 추가하지 않는다.
설명은 기존 글의 description을 사용하며 작성되지 않은 설명을 임의로 만들어 넣지 않는다.

도구 행은 화면 안의 한 위치에만 둔다. 목록 화면에서는 큰 검색 입력을
헤더와 도구 행에 중복 표시하지 않고 헤더의 `검색` 링크가 도구 행으로 이동하도록
설계한다. 검색 input·정렬 select는 44px 높이, 입력은 1px strong-line / 4px 모서리.
검색 placeholder는 `검색`, 접근 가능한 label도 `검색`이다.

**기존 기능 유지:** 한 페이지 8개, 최신순/오래된순은 수정일 우선 정렬이다.
필터·검색·정렬 변경 시 `page`를 초기화한다. 현재 페이지와 전체 수는 counter의
tabular 숫자를 재사용한다. 원형 이전·다음은 44px이며 경계에서는 disabled 0.3이다.
페이지 번호가 많아도 모든 번호가 모바일 화면을 넘도록 나열하지 않는다.
확장 사양은 이전·다음과 `현재 / 전체`를 기본으로 하고, 직접 번호 선택을 표시할
경우에는 같은 텍스트 컨트롤을 제한된 범위로만 배치한다.

### 모바일과 상태

도구 행과 태그는 줄바꿈하며 목록은 한 열을 유지한다. 목록 요약은 최대 3줄,
제목은 전체 내용이 읽히도록 줄바꿈한다. 결과 갱신 시 기존 결과 영역과 도구 행을
유지하고 `글을 불러오는 중입니다.` 텍스트를 상태 영역에 표시한다.
조건에 맞는 글이 없으면 조건 변경·검색 초기화 링크를 같은 영역에 배치한다.

## 4. 게시글 상세

### 데스크톱 구조

```text
공통 헤더
← 글 목록 / 카테고리
게시글 제목 — 긴 제목은 읽기용 title 규모로 여러 줄
설명
수정일 · 날짜        태그 링크
──────────────────────────────────────────────────
Markdown 본문: 최대 800px       목차: 최대 280px
h2, 문단, 이미지, 코드, 표      현재 항목은 파란 글자
                               sticky top 36px
──────────────────────────────────────────────────
← 이전 글                     다음 글 →
공통 푸터
```

외곽은 공통 wrap. 제목·본문의 시작선을 맞추고 글 읽기 폭은 최대 800px로 제한한다.
글 제목은 기존 story-intro의 `clamp(28px,4vw,48px)` / 550 / 1.45를 확장한다.
긴 기술 제목도 잘리지 않으며 Hero의 94px display를 그대로 적용하지 않는다.
읽기 영역 전체를 별도의 굵은 테두리 카드로 묶지 않는다.

>1,100px에서는 `minmax(0,800px) 280px` 그리드와 60px 간격을 사용한다.
실제 가용 폭에 따라 본문은 줄어들 수 있다. 남는 외곽 폭을 억지로 카드 padding으로
채우지 않는다. TOC가 필요 없는 짧은 글은 최대 800px 본문과 동일한 왼쪽 정렬을 유지한다.

### TOC

**기존 데이터:** `lib/content.js`가 h2–h4 제목과 slug를 추출하고,
`MDXContent.js`와 `lib/headings.js`가 렌더링 제목의 ID를 생성한다.
TOC UI는 아직 없으므로 이 데이터를 이용하는 신규 블로그 확장으로 설계한다.

TOC는 `목차` 라벨, 1px 위쪽 선, 14px 텍스트 링크로 구성한다. h3·h4는 기존
inline 간격 16px를 한 단계 들여쓰기에 재사용한다. 현재 항목은 accent와
`aria-current=location`, hover와 focus는 공통 링크 규칙을 사용한다.
현재 항목을 가로막는 큰 강조 배경이나 별도의 진행률 표시를 만들지 않는다.

본문 제목이 둘 이상일 때 표시한다. 제목이 없거나 하나뿐이면 TOC를 생략한다.
앵커 이동은 offset 36px와 native smooth scroll, 모션 축소에서는 즉시 이동한다.
긴 목차의 desktop 최대 높이는 viewport에서 위아래 36px를 뺀 범위로 제한하고
목차 내부만 스크롤한다. 키보드 링크와 URL fragment로도 제목에 도달할 수 있어야 한다.
현재 섹션 추적은 구현 단계의 기능이며 기존 코드에 이미 있다고 가정하지 않는다.

현재 heading 추출기는 ATX h2–h4 및 백틱 코드 fence 중심이다.
향후 TOC 구현 시 explicit id, 중복 heading, MDX heading, 다른 코드 fence 등에서
본문 ID와 TOC ID가 일치하는지 확인해야 한다. 불일치한 앵커를 보여주는 대신
렌더링된 heading과 일치하는 항목만 사용한다.

### 모바일 구조

1,100px 이하에서는 TOC를 제목 정보와 본문 사이의 `<details>`형 블록으로 이동한다.
기본은 접힘, summary `목차`는 최소 44px, 선·화살표는 원본 메뉴 패턴을 따른다.
고정 하단 목차 버튼이나 전체 화면 drawer는 만들지 않는다.

본문은 480px 이하 15px / line-height 2. 이미지와 제목의 시작선은 본문에 맞춘다.
표·코드가 넓어도 전체 페이지는 넓어지지 않으며 해당 영역만 스크롤한다.
이전·다음 글은 800px 이하에서 한 열로 쌓는다.

## 5. 카테고리 페이지

### 카테고리 전체 `/category/`

```text
공통 헤더
카테고리.
───────────────────────────────────────────
카테고리 이름                실제 글 수       →
───────────────────────────────────────────
다른 카테고리 이름           실제 글 수       →
공통 푸터
```

이름·개수·탐색 화살표가 있는 CategoryRow를 사용한다. 각 행의 제목은 itemTitle,
개수는 metadata, 구분선은 line이다. 분야별 신규 색상이나 아이콘 타일은 추가하지 않는다.
현재 `CategoryGrid`의 다열 카드 데이터를 읽을 수 있지만 시각 표현은 공통 행으로 확장한다.

### 특정 카테고리 `/category/[tag]/`

상단 `← 카테고리` 링크 → 실제 카테고리명 → 실제 글 수 → 검색·정렬 → PostRow 목록.
긴 카테고리명에는 articleTitle 크기를 사용한다. 전체 목록과 같은 PostRow,
Pagination, SearchField를 재사용하며 현재 카테고리를 active 텍스트로 표시한다.

카테고리 내 검색은 그 카테고리의 글에만 적용한다. 결과 없음 안내에 현재
검색 범위를 명시하고 `이 카테고리의 모든 글 보기` 링크는 q만 제거한다.
없는 카테고리의 404와 존재하지만 글이 없는 카테고리의 empty 상태를 구분한다.
태그 이름은 실제 콘텐츠에서 가져오고 임의의 분야 이름이나 개수로 대체하지 않는다.

## 6. 검색 화면

### 경로와 탐색 계약

기본 검색은 기존 `/blog/?q=검색어`에 검색 전용 화면 상태를 표시한다.
카테고리 안에서는 해당 경로와 검색 범위를 유지한다. 링크 공유와 뒤로 가기 시
q·sort·page가 복원되어야 한다. 별도 검색 서비스나 검색 라우트는 이번 사양에 필요하지 않다.

**현재 검색 범위는 제목·description·태그이다.** Markdown 본문 전체가 검색된다고
안내하지 않는다. 검색 동작을 본문 검색으로 확장하는 작업은 이번 디자인 문서의 범위 밖이다.
원래 문자열 포함 방식으로 가능한 결과를 사용하며 유사어·오타 교정·추천 검색어를 지어내지 않는다.

### 구성

```text
공통 헤더
검색.
───────────────────────────────────────────
label 검색 / input [검색어] / 실행
실제 결과 수 · 전체 글 또는 현재 카테고리
검색 초기화                         정렬
───────────────────────────────────────────
공통 PostRow 결과
공통 Pagination
공통 푸터
```

페이지 제목 `검색.`과 입력에 역할을 나누며 긴 검색어를 display 제목으로 확대하지 않는다.
검색어는 input에서 확인·수정하고 결과 요약 문장에서 안전하게 줄바꿈한다.
일치 강조가 필요한 경우 새 노란색 mark 대신 기존 accent 또는 weight 550을 사용한다.
HTML 문자열 삽입으로 검색어를 렌더링하지 않는다.

| 상태 | 표시 |
| --- | --- |
| 입력 전 | label·input, `제목, 설명, 태그에서 검색합니다.` 안내 |
| 결과 있음 | 실제 검색어·범위·결과 수 + 공통 PostRow |
| 갱신 중 | 입력값은 유지, 결과 영역 status `검색 중입니다.` |
| 결과 없음 | `검색 결과가 없습니다.` / `다른 검색어로 검색해 보세요.` / 초기화 링크 |
| 실패 | `검색 결과를 불러오지 못했습니다.` / 실제 재시도 가능한 동작 |
| 초기화 | q와 page를 제거, category와 sort 범위는 유지 |

모바일 input과 실행 버튼은 가용 폭에 맞추고 44px 높이를 유지한다.
결과 개수 알림은 aria-live polite로 제공하되 입력할 때마다 과도하게 알리지 않도록
최종 갱신된 결과 상태만 알린다. 원본에 없는 모달 검색·어두운 전체 화면 검색은 추가하지 않는다.

## 7. 블로그 추가 UI 상세 규칙

### 7.1 Markdown 본문

| 요소 | 설계 규칙 | 원본과의 관계 |
| --- | --- | --- |
| 문단 | 최대 800px, 17px/2 또는 모바일 15px/2, ink, 문단 간 16px | 기존 story-copy·intro 크기·폭·여백 확장 |
| h2 | section 타입, 상단 50px / 하단 25px | 원본 섹션 여백·heading 하단 재사용 |
| h3 | itemTitle, 상단 32px / 하단 16px | 기존 값 조합 |
| h4 | 16px/550, 상단 24px / 하단 12px | 기존 본문·간격 조합 |
| 목록 | 본문 타입, 들여쓰기 24px, 항목 간 8px, ordered 번호 유지 | 필요한 Markdown 문법 확장 |
| 본문 링크 | accent, underline, offset 5px; hover도 링크 역할 유지 | 기존 story-links 표현 확장 |
| 인용문 | lineStrong 1px 왼쪽 선, padding-left 24px, 본문 ink | 기존 선·여백 조합, 새 callout 색 없음 |
| hr | line 1px, 위아래 40px | 기존 섹션 divider 재사용 |
| 이미지 | max-width 100%, 원본 비율, 프레임·그림자 없음, 캡션 12px/1.6 | 원본 이미지 처리와 사용자 선호 적용 |
| 표 | 헤더 subtle / ink, 셀 padding 12px·16px, 1px line, 내부 스크롤 | 기존 팔레트·선 확장 |
| inline code | mono, 0.9em, subtle 배경, 4px 모서리, inline padding 4px·6px | 기존 reset·컨트롤 값으로 확장 |
| strong / em | strong은 현재 폰트의 굵은 강조, em은 본문 글꼴 italic | Markdown 의미 유지. serif로 본문 전체를 바꾸지 않음 |

상세 Hero가 페이지 h1을 담당하고 새 글의 본문 작성 규칙은 h2부터 시작한다.
기존 본문 콘텐츠를 디자인 작업만으로 다시 쓰지는 않는다. 본문에 h1이 있는 기존 글은
구현 시 표시 위계를 검토하고 글 제목 규모로 반복 확대하지 않는다.
일반 문단마다 구분선을 붙이지 않고 heading도 모든 단계에 새 번호·장식을 붙이지 않는다.

### 7.2 코드 블록

원본 story-media의 배경 media, 6px 모서리, desktop padding 24px / mobile 16px를
재사용하고 1px line 테두리를 확장한다. 본문 폭 안에서만 스크롤한다.
코드는 mono 14px / 1.7이며 공백·개행을 보존한다. 기본은 줄바꿈 없이 가로 스크롤한다.

상단 언어 라벨은 12px muted, 실제 코드 언어가 없으면 라벨을 생략한다.
오른쪽 `복사`는 44px 조작 영역의 작은 텍스트 버튼이다. 성공은 같은 위치의
`복사됨`, 실패는 `복사하지 못했습니다. 코드를 직접 선택해 주세요.`로 표시한다.
명시적인 사용자 클릭 때만 원문 코드를 복사한다. 버튼·언어 라벨·줄 번호는
복사할 코드에 포함하지 않는다.

문법 강조는 ink / muted / accent와 weight만으로 한정한다. 기본 본문 코드는 ink,
주석은 muted, 필요한 문법 식별에 accent를 사용할 수 있다. 새 문법별 색 테마,
터미널의 빨강·노랑·초록 장식 버튼, 기본 줄 번호, 코드 줄 강조 애니메이션은 추가하지 않는다.
코드 내용이 없는 경우 복사 버튼을 생략한다. 키보드로 스크롤할 수 있게 하되
모든 짧은 코드 블록을 불필요한 탭 경유 지점으로 만들지 않는다.

### 7.3 태그와 분류

태그는 작은 텍스트 링크를 gap 12px로 배치하며 필요하면 줄바꿈한다.
기본은 ink, hover·현재 카테고리는 accent. 두꺼운 pill 배경을 만들지 않는다.
필터로 사용될 때만 44px 조작 영역과 현재 상태를 제공한다.
읽기용 텍스트와 클릭 가능한 분류를 실제 링크 역할로 구별한다.

카테고리 이름은 사용자 선호대로 `카테고리`로 표시한다. 개발·성능·AI 등
현재 글 데이터의 이름을 그대로 쓰고 시각적 편의를 위해 분류를 합치거나 재명명하지 않는다.

### 7.4 이전 글 / 다음 글

본문 하단에 1px 선과 위아래 40px 여백을 사용한다. desktop 두 열, gap 60px.
좌측 `이전 글`·제목·왼쪽 화살표, 우측 `다음 글`·제목·오른쪽 화살표.
글 제목은 itemTitle, label은 metadata이며 hover는 제목 색상만 변경한다.

이전·다음 데이터는 현재 `getAdjacentPosts()`의 반환값을 그대로 사용한다.
시각 개편만으로 방향을 날짜 기준으로 뒤집거나 같은 카테고리로 제한하지 않는다.
글이 한쪽에 없으면 해당 링크를 생략하고 빈 placeholder 카드를 보여주지 않는다.
두 링크 모두 없으면 탐색 영역을 생략한다. 모바일은 실제 존재하는 링크를 위아래로 배치한다.

### 7.5 모바일 내비게이션

원본 44px 햄버거 버튼, 22px 선 아이콘, 180ms X 전환, surface 팝오버,
1px line, 원본 popover shadow를 유지한다. 메뉴 항목은 원본과 같은 최소 46px 높이.
컨텐츠는 홈 / 글 / 카테고리 / 검색 / 실제 GitHub 링크로 구성한다.
언어 메뉴는 현재 개인 블로그가 다국어 기능을 갖추지 않았으므로 자동 추가하지 않는다.

테마 버튼은 헤더의 44px 원형 컨트롤을 유지한다. 폭이 좁으면 검색 입력은
헤더 밖으로 이동하고 `검색` 메뉴 항목이 실제 검색 화면으로 이동한다.
원본의 네이티브 details 동작을 유지하며 전체 화면 패널·배경 dim·새 슬라이드 애니메이션은 없다.
기존 사용자 페이지가 입력 중인 검색어를 메뉴 열림·닫힘만으로 잃지 않게 한다.

아래는 향후 구현 시의 책임 매핑이다. 이번 작업에서는 이 파일들을 수정하지 않는다.

기존 글 URL, canonical alias, 검색 범위, 수정일 우선 정렬, 분류 slug는 시각
설계 때문에 변경하지 않는다. 프로젝트의 기존 콘텐츠·메타데이터를 디자인 데이터로 사용한다.

검색 화면 분기 등이 새로 구현되었거나 검증되었다는 의미가 아니다.
